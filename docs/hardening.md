# Platform Hardening & Security Audit (P9.3)

Audit verified against the live cluster on 2026-10-04.

## 1. Non-Root Containers

All 6 custom container definitions enforce unprivileged execution:
- `docker/model_api.Dockerfile`: `USER 10001:10001`
- `docker/training.Dockerfile`: `USER 10001:10001`
- `docker/mlflow.Dockerfile`: `USER 10001:10001`
- `docker/remediator.Dockerfile`: `USER 10001:10001`
- `docker/drift_monitor.Dockerfile`: `USER 10001:10001`
- `docker/retrain.Dockerfile`: `USER 10001:10001`

Verified via Hadolint: 0 errors/warnings (`hadolint docker/*.Dockerfile`).

## 2. Resource Quotas and Limits

All workloads define explicit `requests` and `limits` for CPU and Memory:
- `model-api`: requests `100m / 256Mi`, limits `500m / 512Mi`
- `drift-monitor`: requests `200m / 512Mi`, limits `1000m / 1Gi`
- `retrain`: requests `200m / 512Mi`, limits `2000m / 2Gi`
- `remediator`: requests `50m / 128Mi`, limits `250m / 256Mi`
- `mlflow`: requests `200m / 1Gi`, limits `2000m / 4Gi`
- `postgres`: requests `100m / 256Mi`, limits `500m / 1Gi`
- `redis`: requests `50m / 64Mi`, limits `200m / 256Mi`
- `minio`: requests `100m / 256Mi`, limits `500m / 512Mi`
- `kube-prometheus-stack` & `loki`: tuned for 8 CPU / 16 GB laptop profile.

## 3. NetworkPolicy Isolation

Provisioned via `deploy/charts/model-api/templates/networkpolicy.yaml`:
1. `model-api-default-deny`: Default-deny ingress and egress for namespace `serving`.
2. `model-api`:
   - Ingress: Whitelisted on TCP port 8080 from all namespaces (client traffic and Prometheus scraping).
   - Egress:
     - DNS resolution on UDP/TCP port 53.
     - Upstream data services in namespace `data`: Redis (`6379`), Postgres (`5432`), MLflow (`5000`), MinIO (`9000`).
     - All other egress blocked.

## 4. RBAC Least-Privilege

ServiceAccounts in non-privileged namespaces are constrained to minimal roles:
- `observability:remediator`: Granted `get`, `list`, `patch` on `deployments` and `horizontalpodautoscalers` in `serving` only. Cannot read Secrets or access any other namespace.
- `observability:drift-monitor`: Granted `create`, `get`, `list` on `jobs` in `data` and `get` on `configmaps`. Cannot delete deployments, read secrets, or modify cluster state.
- `serving:model-api`: Uses default ServiceAccount with no API server permissions.

Verified via `kubectl auth can-i`: all unauthorized verb queries returned `no`.
